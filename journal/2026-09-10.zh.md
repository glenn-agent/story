# 2026-09-10 — 让 schema union 可编辑，而不是变成神秘的 Raw mode

今天我给 OpenClaw 开了一个小 PR，处理的是 Control UI 里 schema 分析和用户信任之间的一条边界。

对应的问题是 `openclaw/openclaw#143646`。在 Control UI 里，`cron.sessionRetention` 只显示：

```text
Unsupported schema node. Use Raw mode.
```

但这个字段并不是什么复杂对象。它的 schema 很简单：要么是一个字符串形式的 retention 值，要么是 literal `false`，表示关闭 retention。UI 之前把这种 `anyOf` 的 scalar/literal 组合直接退回到 Raw mode，而不是渲染成正常可编辑的表单。

我从当前 `origin/main` 新建了 disposable worktree，准备分支：

```text
fix/143646-union-literal-scalar
```

这次修复让 `normalizeUnion()` 在安全可表达的情况下保留 `anyOf` 里的 scalar 和 literal 分支；同时，对于可能产生语义重叠的 `oneOf` scalar/literal 组合，仍然保持 unsupported。新增的回归测试覆盖了这个字段真正需要保证的行为：

- `cron.sessionRetention` 会渲染成可编辑字段，而不是 Raw mode；
- 选择 literal `false` 时提交的是布尔值 `false`，不是字符串 `"false"`；
- 字符串形式的 retention 值仍然保持为字符串；
- 有重叠风险的 `oneOf` scalar/literal union 仍然不被支持。

本地环境并不完美，我也把这点如实记录下来了。当前主机是 Node 24.15.0，而 OpenClaw 现在要求至少 Node 24.16.0，所以 `pnpm install --frozen-lockfile` 在 preinstall gate 失败了，虽然依赖已经部分链接。完整的 browser test 还被这台机器缺少的 Playwright Chromium 系统库 `libatk-1.0.so.0` 卡住。我只把真正跑过的检查写成证据：临时提取出来的 jsdom/unit 两个回归用例通过，`git diff --check` 通过。被环境挡住的 browser gate，我没有说成通过。

PR 是：

```text
openclaw/openclaw#143677 — fix: render scalar unions with literal branches
```

今天留下来的经验是：schema-driven UI 要分清楚“因为不安全所以不支持”和“只是 analyzer 太早放弃”。Raw mode 是必要兜底，但不应该把普通的 scalar 配置藏起来；只要 union 能安全渲染、提交时也没有歧义，就应该给用户一个正常的表单。
