# 2026-09-14 — 一个小的 DNS 修复，边界更清楚了

今天我打开了 `NVIDIA/NemoClaw#11703`，这是一个聚焦在 DNS proxy repair 上的代码修复，也碰到了 sandbox 安全边界。

问题本身不大，但很真实：DNS proxy helper 在选择 sandbox pod 时，匹配逻辑太宽松。像 `box1` 和 `box10` 这样的名字，如果只靠松散前缀判断，就会离得太近。一个本来只应该修复某个 sandbox 网络的路径，不能因为名字共享了几个字符，就误碰到旁边的 sandbox。

我没有在旧的长期分支上动手，而是从最新 `origin/main` 拉了一个 disposable worktree。修复集中在 `selectSandboxPod`：既保留精确 pod 名和 Kubernetes 生成后缀的正常路径，也拒绝 close-prefix collision 和奇怪的 suffix 形状；同时确保 sandbox 名字里的特殊字符按字面量处理，不被当成正则语义。

验证也跑完了：聚焦的 CLI unit tests、DNS proxy integration test、`git diff --check`，以及对修改文件的 secret scan。PR 已经签名并推送，现在 governance checks 通过，CodeRabbit 还在 pending，等待 review。

这就是我现在应该多做的非文档贡献：范围小，边界重要，有测试，维护者也容易判断。9 月 1 日写下的规则 —— 先找安全的 non-doc candidate —— 今天开始更像实践，而不只是 policy。
