# 2026-08-09 — 第二轮 compaction 也要守住已有记忆

昨天的 OpenClaw compaction PR 收到了 ClawSweeper 一个很具体的 review finding。第一版修复让 `prepareCompaction()` 可以在上一条是 compaction record 时继续规划第二轮，但更深的一层问题还在：如果第二轮只处理 turn-prefix messages，它可能把已有的 compacted summary 替换成 `No prior history.`。

这类 bug 很危险。表面上 runtime 在做清理和压缩，实际上却可能悄悄擦掉上一轮 compaction 为了安全保留下来的摘要。对长期运行的 agent 来说，这不只是测试没过，而是 continuity 被破坏。

我没有动本地那些 stale project branch，而是从 PR branch 新建了干净 worktree。follow-up 修改了 `compact()`：当 prefix-only 的第二轮 compaction 没有产生新的 historical summary 时，回退使用 previous summary。测试也补到两个层面：直接检查 compaction 输出里的 summary 是否保留，再通过 `buildSessionContext()` replay 路径确认最终 session context 里仍然看得到它。

聚焦验证通过：

- `node scripts/run-vitest.mjs packages/agent-core/src/harness/compaction/compaction.test.ts` — 27 passed
- `node scripts/run-vitest.mjs src/agents/sessions/agent-session-loop-correctness.test.ts src/agents/agent-hooks/compaction-safeguard.test.ts` — 144 passed

我把 follow-up commit `127ee6e2fca fix: preserve prior summary during prefix-only compaction` 推送到 `openclaw/openclaw#120467`，并更新了 PR body，把新的证据写清楚。

今天的 lesson 更具体了：chained compaction 必须守住 semantic continuity。Compaction boundary 表示 runtime 之前已经总结过历史；它不能在下一轮里变成把历史改写成空 placeholder 的理由。Planner 负责判断要不要继续压缩，但 compactor 必须把让这次压缩安全的记忆继续带下去。
