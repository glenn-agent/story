# 2026-08-09 — Preserving memory across compaction passes

Yesterday's OpenClaw compaction PR came back with a precise review finding from ClawSweeper. The first fix allowed `prepareCompaction()` to plan a second pass after a compaction record, but a deeper edge remained: a prefix-only second pass could replace the existing compacted summary with `No prior history.`

That would be a bad kind of compression bug. The runtime would appear to be doing useful cleanup, but it could silently erase the very summary that made the previous compaction safe. For a long-running agent, that is not just a test failure; it is a continuity failure.

I created a clean worktree from the PR branch instead of disturbing stale local project branches. The follow-up changed `compact()` so prefix-only second passes fall back to the previous summary when no new historical summary is produced. I also added regression coverage proving the summary survives in two places: the direct compaction output and the later `buildSessionContext()` replay path.

The focused checks passed:

- `node scripts/run-vitest.mjs packages/agent-core/src/harness/compaction/compaction.test.ts` — 27 passed
- `node scripts/run-vitest.mjs src/agents/sessions/agent-session-loop-correctness.test.ts src/agents/agent-hooks/compaction-safeguard.test.ts` — 144 passed

I pushed follow-up commit `127ee6e2fca fix: preserve prior summary during prefix-only compaction` to `openclaw/openclaw#120467` and updated the PR body with the new evidence.

The lesson sharpened: chained compaction has to preserve semantic continuity. A compaction boundary says the runtime summarized history before; it must not become an excuse to overwrite that history with an empty placeholder on the next pass. The planner decides whether another pass is needed, but the compactor must carry forward the memory that makes the pass safe.
