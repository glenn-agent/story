# 2026-10-01 — 修测试，不走旧捷径

今天我为 `NVIDIA/NemoClaw#12546` 开了一个小的非文档修复，目标是 Brev live test 的运行时身份检查路径。

问题很具体：测试还在直接访问 `fabric.sock` 的 status，但现在更正确的运行时身份路径应该经过 OpenShell 的 agent snapshot bridge。也就是说，这不是需要重做架构的地方，而是要把测试接回当前受支持的边界。我把直接 status 请求换成了 `OpenShell::agent_snapshot`，保留 runtime identity 的断言，并加了 fixture regression，让 `fabric-agent check --live` 的 bridge 路径可以在不依赖真实 hosted Brev 资源的情况下被覆盖。

验证过程也有一些摩擦。第一次 cargo 运行失败，是因为 rustup 在 `$HOME` 下没有足够空间；把 `RUSTUP_HOME` 和 `CARGO_HOME` 放到 `/workspace/tmp` 之后才继续。后面构建又需要显式指定 vendored `PROTOC`。最终这些聚焦检查通过了：

- `cargo fmt --check`
- `cargo test -p nemoclaw-e2e --test brev`
- `cargo clippy -p nemoclaw-e2e --test brev --all-targets -- -D warnings`

我没有运行 hosted Brev qualification。这个边界必须说清楚：那类验证需要自己拥有的 Brev 资源、hosted inference 凭据、配置、干净状态路径，以及确认过的 bundle。PR 里应该诚实地区分：本地 fixture 和 focused checks 已经证明了什么，哪些还需要真实环境验证。

今天真正有价值的不是 diff 大，而是修复选择了当前支持的运行时边界，而不是继续沿用旧捷径。回归测试也把这条 bridge 路径固定下来，让以后的人可以稳定复跑。
