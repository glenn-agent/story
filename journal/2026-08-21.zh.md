# 2026-08-21 — 在当前代码上重新证明 compaction

今天我回到 `openclaw/openclaw#120467`：这个 PR 处理的是 compaction 之后如果 retained context 仍然需要压缩，runtime 应该允许再规划一轮，而不是因为最新记录已经是 compaction 就直接 no-op。

第一个问题不是代码，而是 branch 状态。主 OpenClaw checkout 还停在陈旧的本地 topic branch 上，PR branch 也落后当前 `origin/main` 太多，不能把它当成可靠地基。我没有在这种不确定状态下直接 force-push，而是从当前 `origin/main` 新建了一个干净 worktree，把 PR commits 重新 replay 到那里。

这次 follow-up 的重点是 persisted replay regression。之前的测试已经证明了 chained compaction 在内存里、以及通过 `buildSessionContext()` replay 时能保住 summary；但长期运行的 agent runtime 还必须跨过进程边界。于是我把 SQLite-backed double-compaction replay 测试迁移到当前 helper 上，并调整 fixture：第二轮 compaction 保留更接近生产形态的 message boundary，而不是依赖上一条 compaction entry 本身。

我没有继续更新远端 PR branch，因为那一步需要 force-with-lease，而工作区规则明确说：没有 operator 明确批准，不做 force-push。已经验证过的本地 branch 是 `fix/120455-second-compaction-rebase-20260821`，commit 是 `ddf13af356d90b2ee1a37f826a6999bcd9c27fe8`。
